# DB 스키마 검증 결과

산업현장 안전관리 AI 에이전트 · 작성 C · 2026-10-27

- 실행 환경: Windows Git Bash + Docker Desktop, MySQL 8.4
- 실행 명령: `bash verify/verify.sh`
- 계정: 업무 DB는 root가 아닌 앱 계정, 지식 DB는 `kb_owner` (실제 운영과 같은 조건)

## 6. 검증 과정에서 고친 것

| 문제 | 원인 | 조치 |
| --- | --- | --- |
| V2 적용 중 `ERROR 1215 Cannot add foreign key constraint` | `account_tokens.user_id`가 생성 컬럼(`active_key`)의 재료인데 FK에 `ON DELETE CASCADE`를 걸었음. MySQL이 허용하지 않음 | CASCADE 제거 (사용자는 지우지 않고 상태로 관리). README 체크리스트에 규칙 추가 |
| 테스트 개수 표기 197 → 195 | 개수를 셀 때 함수 정의 줄 2개까지 포함 | README·안내 수치 정정 |
| "TBM 날짜와 다른 날짜로 작업 연결" | 날짜 불일치가 아니라 중복 키(1062)로 막히고 있었음 | 날짜 불일치(1452)로 막히는지 확인하도록 테스트 수정. **다음 실행에서 확인 필요** |
| Windows에서 실행 안 됨 | Git Bash 경로 변환, CRLF, 초기화 대기 무한 루프 | 경로 변환 끔, `.gitattributes`로 LF 고정, 3분 제한 + 실패 시 로그 자동 출력 |

## 7. 다시 돌리는 법

```bash
# Windows: Docker Desktop 켜고 Git Bash에서
bash verify/verify.sh
# 실패 원인을 볼 때: 끝나도 검증용 컨테이너를 남김
KEEP=1 bash verify/verify.sh
```

마지막 줄이 `결과: 통과 195 / 실패 0`이면 성공이다. 스키마를 바꾼 PR은 이 결과를 함께 올린다.
